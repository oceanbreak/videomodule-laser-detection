# Laser Dataset Inspector

Интерактивный анализ размеченных пар лазерных отметок на подводных снимках. Порядок кадров берётся из `lasers.csv`. Дата и время в имени файла не используются для определения сетапов, сортировки или интерпретации съёмки.

## Установка и запуск

Проект поддерживает Python 3.9 и 3.11. Выполняйте команды из корня клонированного
репозитория. Анализ данных, калибровка и цветовые детекторы работают на CPU.
PyTorch нужен для U-Net. Диагностика проверяет PyTorch и torchvision.
Оба пакета отсутствуют в зависимостях проекта, включая `[dev]`.

### Windows CPU, Python 3.11

В PowerShell создайте отдельное окружение.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m laser_detection.check_environment
Copy-Item config.example.yaml config.local.yaml
```

При отсутствии PyTorch диагностика сообщает `CUDA forward/backward: SKIPPED` и
завершается успешно в обычном режиме.

### Windows GPU, Python 3.9, GTX 1070

Активируйте **существующее** окружение с `torch==2.7.1` и
`torchvision==0.22.1` из индекса PyTorch cu126. Используйте его `python`
и проверьте путь к интерпретатору и версии пакетов до установки проекта.

```powershell
python -c "import sys, torch, torchvision; print(sys.executable); print(sys.version); print(torch.__version__, torchvision.__version__, torch.version.cuda)"
python -m pip install -e ".[dev]"

python -m laser_detection.check_environment --require-cuda
```

Установка проекта не запрашивает установку или замену PyTorch. Для
`config.local.yaml` используйте существующий файл или скопируйте шаблон, если
настраиваете проект впервые.

GTX 1070 имеет compute capability 6.1. Строки `+cu126`, `CUDA available: True`
и список архитектур сборки сами по себе не подтверждают выполнение ядер.
Диагностика выводит модель GPU, compute capability, архитектуры сборки и cuDNN.
Тест выполняет свёртку, вычисление loss и backward на выбранном GPU, синхронизирует
CUDA и проверяет результаты и градиенты. `--require-cuda` возвращает ненулевой
код при пропуске или ошибке. Если устройств несколько, укажите `--device N`.
Статус `PASSED` подтверждает эти операции для проверенной связки GPU, драйвера
и PyTorch. Проверку на GTX 1070 нужно выполнить на самой машине.

## Геометрическая калибровка

Запустите `jupyter lab` из корня проекта и откройте
`notebooks/02_geometry_calibration.ipynb`. Ноутбук использует тот же
`config.local.yaml`, что и обзор датасета. CSV-импорт упорядочивает точки слева
направо и при равных X сверху вниз. Подгонка использует только полные пары.
Просмотр фотографий доступен по запросу.

Для каждого сетапа RANSAC независимо подбирает прямую для каждого лазера.
Каждая гипотеза строится по двум различным точкам. Выбирается гипотеза с
наибольшим числом точек внутри порога, а при равенстве — с меньшей суммой
расстояний этих точек. Ортогональная регрессия уточняет прямую по этой группе.
Остаток равен перпендикулярному расстоянию `|ax + by + c|` в пикселях при
`a² + b² = 1`. Угол между прямыми — наименьший неориентированный угол в градусах.
Остаток пары равен максимуму двух остатков. Коридор `±t` принимает пару, если
обе точки удалены от соответствующих прямых не более чем на `t` пикселей.

### Настройки

Необязательная секция `calibration` в `config.local.yaml` переопределяет значения
из [шаблона](config.example.yaml).

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `ransac_threshold` | 10 px | Порог включения точки в консенсус RANSAC |
| `ransac_trials` | 256 | Число гипотез на прямую |
| `corridor_thresholds` | 5, 10, 20, 30, 50 px | Исследуемые полуширины коридоров |
| `training_sizes` | 10, 20, 30, 50, 100, 200 | Размеры выборок для подгонки |
| `repetitions` | 30 | Повторения для каждого размера и каждой доли загрязнения |
| `contamination_fractions` | 0, 0.05, 0.10, 0.20, 0.30 | Доли подменённых обучающих пар |
| `contamination_training_size` | 50 | Число обучающих пар в эксперименте с загрязнением |
| `random_state` | 42 | Начальное значение генератора случайных чисел |

Оценка **in-sample** использует все размеченные пары сетапа и для построения
прямых, и для расчёта остатков. Оценка **out-of-sample** строит прямые на
случайно выбранных кадрах и измеряет качество на всех оставшихся размеченных
кадрах того же сетапа. Размеры выборок без хотя бы одного удержанного кадра
помечаются как `skipped`. Вырожденные подгонки помечаются как `failed`.
Медиана и интервал P5–P95 между повторениями вычисляются по успешным запускам.
В агрегатах отдельно указано число успешных и неудачных запусков.

Эксперимент с загрязнением заменяет целые обучающие пары случайными пиксельными
координатами, сохраняя порядок точек слева направо. Число замен округляется до
ближайшего целого, половина округляется вверх. В пределах повторения все доли
сравниваются на одном разбиении. Удержанные точки всегда исходные. Исследование
характеризует геометрию разметки. Точность реального детектора и характер его
ошибок потребуют отдельной проверки.

## Цветовые baseline-детекторы

Откройте `notebooks/03_detection_baselines.ipynb` в JupyterLab после обновления
окружения командой `python -m pip install -e ".[dev]"`. Для этого ноутбука нужны
локальные CSV и фотографии. Существующие ноутбуки обзора и калибровки продолжают
работать со своей конфигурацией.

Все четыре метода уменьшают BGR-кадр с 3072×2048 до 1536×1024 через `INTER_AREA`.
HLS строит маску по двум интервалам оттенка и общим границам яркости и насыщенности.
Red Boost вычисляет `R − (G + B) / 2` в знаковом представлении и включает пиксели
строго выше порога. HSV Legacy и HSV Narrow преобразуют BGR в стандартный
8-битный HSV OpenCV. Оба используют Hue `[0, 10]`, Saturation `[100, 255]` и
Value `[150, 255]`. Второй диапазон Hue составляет `[150, 179]` у Legacy и
`[170, 179]` у Narrow. Верхняя граница 179 сохраняет эффект исходной границы
200 у Legacy, поскольку стандартный HSV OpenCV ограничен 179. По маске выбираются две крупнейшие 8-связные компоненты.
При равной площади приоритет у меньшей метки OpenCV. Даже компонент из одного
пикселя участвует в выборе. Центроиды сортируются по X, затем по Y, и возвращаются
в исходное разрешение с поправкой на центры пикселей. При меньшем числе компонент
координаты пары отсутствуют. Это намеренно простой baseline без геометрической
коррекции, сглаживания, морфологии и фильтрации компонент.

### Настройки и разбиение

В `config.local.yaml` можно переопределить секцию `detection` из
[шаблона](config.example.yaml). Стартовые значения HLS — интервалы Hue
`[0, 10]` и `[170, 180]` в шкале OpenCV, Lightness `[40, 255]` и
Saturation `[100, 255]`. Стартовый порог `boost_threshold` равен 40.
Границы HLS включены. Порог Red Boost строгий. Эти значения служат отправной
точкой для эксперимента. Границы HSV настраиваются в `hsv_legacy`
и `hsv_narrow`. Размер обработки задают `width` и `height`, а условия
замера — `warmup_frames` и `opencv_threads` (по умолчанию 5 кадров и 1 поток).

Задайте `data.series_csv` для воспроизводимого разделения на train,
validation и test. Локальный файл с разделителем `;` содержит столбцы
`image;series_id` и покрывает каждый кадр разметки ровно один раз. Укажите
идентификаторы как минимум трёх независимых серий съёмки. Серии назначаются
целиком, примерно в пропорции 60/20/20 по числу серий, с `split_seed`
(по умолчанию 42). Сетапы и даты в именах файлов не определяют серии.
Без этого файла весь запуск помечен как `exploratory`.

Для нового сравнения измените пороги в конфигурации и выполните ноутбук заново.
Подбирайте пороги по train/validation, сохраняя один и тот же состав разбиения.
После фиксации порогов установите `FINAL_TEST = True` для финального отчёта на test.

### Метрики и экспорт

TP/FP/FN/TN оценивают наличие пары. Крупная координатная ошибка сама по себе
не меняет TP на FN. Среднее, медиана, P90 и P95 координатных ошибок считаются по
евклидовым расстояниям обеих точек только на кадрах с размеченной и предсказанной
парой. Для Recall@5/10/20 в знаменателе все доступные размеченные пары.
Успех требует, чтобы обе точки уложились в порог в исходных пикселях.
Отсутствие предсказания считается промахом, а ошибки чтения учитываются отдельно.

Замер выполняется последовательно на одном CPU и наборе кадров с циклическим
смещением порядка методов. Время чтения и визуализации исключено. Полное время включает
возврат координат в исходный масштаб. FPS равен обратной величине среднего
полного времени в секундах. CPU, версия, сборка и число потоков OpenCV записываются
в параметры запуска вместе с версиями зависимостей.

В ячейке экспорта установите `EXPORT = True` и задайте `RUN_NAME`.
Экспорт создаёт новую папку в `results/detection_baselines/` или в
`output.detection_directory`. Имя по умолчанию — `hsv_comparison`. Для
повторного экспорта выберите новое имя. Сохраняются четыре таблицы
`predictions_hls.csv`, `predictions_red_boost.csv`, `predictions_hsv_legacy.csv`
и `predictions_hsv_narrow.csv` со статусом
чтения, наличием пары, координатами исходного разрешения, числом компонент,
площадями двух выбранных компонент в пикселях маски, временем этапов в наносекундах,
ошибками обеих точек, сетапом и частью разбиения. Отдельно сохраняются метрики по
методам и сетапам, сводка времени, `dataset_split.csv`, `experiment_config.json`
и автономные Plotly-графики в `figures/`. Покадровые таблицы подходят для
последующего анализа геометрии без повторного детектирования. Храните их локально,
вместе с разметкой и фотографиями.

В диагностике кадра доступны четыре маски с разметкой и центроидами.
Отдельные подборки показывают кадры, где только один из HSV Legacy и Red Boost
локализует обе точки в выбранном допуске. По умолчанию допуск равен 10 px.

Для повторного построения сравнительной таблицы из CSV выполните ячейку
импортов и ячейку «Сравнение из сохранённых CSV» с `SAVED_RUN` и `SAVED_SPLIT`.
Она читает `metrics_by_method.csv` и `timings.csv`. Для прежнего двухметодного
экспорта в корне папки результатов задайте `SAVED_RUN = "."`.

## U-Net для детекции лазерных отметок

Четырёхуровневая U-Net получает уменьшенный RGB-кадр и предсказывает одну карту
логитов. Целевые карты строятся при чтении кадра из исходных координат с учётом
центров пикселей. По умолчанию `binary_circle` рисует круги радиуса 4 px.
Для `gaussian` с `sigma: 3` карта — максимум двух гауссовых пятен.
Кадр без разметки получает нулевую карту. Радиус и sigma заданы в пикселях входа
сети. Для кругов доступны `bce`, `dice`, `bce_dice`, для гауссовых пятен —
`weighted_mse`. Параметр `foreground_weight` усиливает вклад области лазеров в
BCE и MSE. Инференс применяет sigmoid, ищет локальные максимумы, подавляет
соседние пики в радиусе `nms_radius` и выбирает пару выше порога `confidence`.

Для CPU на Windows с Python 3.11 установите PyTorch в CPU-окружение из
инструкции выше. Выполняйте команду его интерпретатором:

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m laser_detection.train --profile cpu
```

Для GTX 1070 активируйте существующее окружение Python 3.9 с PyTorch
`2.7.1+cu126` и torchvision `0.22.1+cu126`. Пакеты PyTorch устанавливаются
отдельно от проекта. Перед первым обучением выполните проверку:

```powershell

```

Для GPU ожидается `PASSED` в диагностике и исполненный CUDA-тест pytest.

Оба профиля используют float32. Параметры описаны в

загрузка выполняется с `num_workers: 0`. CLI поддерживает workers из профиля.

### Разбиение, обучение и результаты

Укажите `data.dataset_split_csv`, чтобы явно переиспользовать сохранённое
разбиение. При наличии одного экспорта baseline оно подбирается автоматически.
Режим по сериям использует `data.series_csv` и проверяет, что серия целиком
попадает в одну часть. При отсутствии серий случайное разбиение по кадрам
помечается как `exploratory`. Сохранённый список кадров проверяется при
возобновлении и сравнении. Подбирайте настройки только по train/validation.

CLI и Jupyter показывают отдельные индикаторы train и validation для каждой
эпохи. Loss на индикаторе усредняется по всем обработанным изображениям,
включая неполные батчи. Чтобы оставить только итоговые строки эпох, задайте
`show_progress: false` в выбранном профиле `unet.cpu` или `unet.cuda`.

Обучение с Adam сохраняет `best.pt` по validation loss, `last.pt` для
возобновления, историю эпох, конфигурацию и разбиение в новой папке
`results/unet/`. Для возобновления увеличьте `epochs` в профиле до нового
общего числа эпох и передайте `--resume results/unet/RUN/last.pt`.
Загрузка использует `state_dict` и `weights_only=True` в PyTorch.


Сравнение использует одинаковые доступные кадры у U-Net и HSV Legacy. Метрики
считаются в исходных пикселях и сохраняются вместе с предсказаниями, сводкой
времени и разбивкой по сетапам. Время включает подготовку кадра и
постобработку, исключает чтение с диска, а CUDA синхронизируется. В таблице
указаны устройство и входное разрешение каждого метода. Для сравнения CPU и
CUDA запустите оценку одного checkpoint и одной части данных дважды с
соответствующим `--device`. Используйте `--run-name` для именованных запусков.
